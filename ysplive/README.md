# ysplive（央视频直播）· 飞牛 fnOS 原生安装包

把上游 [tmxk2020/ysp-live](https://github.com/tmxk2020/ysp-live)（原本是 Docker + Python/Node 的 OpenWrt 软路由方案）改造成 **飞牛 fnOS 原生 FPK 应用**，应用名 **ysplive**：不再需要 Docker，装完在桌面点开就是一块电视式的直播界面——左侧频道列表、中间频道信息、右边直播画面，带真实节目单，点两下就能在网页里看直播；右上「管理」进去可以改站点信息、频道名称/分组/地址、加自定义频道；同时照旧对外输出标准 M3U 订阅给电视和播放器。界面**同时监听 IPv4 与 IPv6**。

## 产物

| 文件 | 说明 |
| --- | --- |
| `ysplive-1.1.12-fnos-all.fpk` | 安装包，x86 与 ARM 通用（纯 Python 文本文件 + 网页资源，无架构二进制） |
| `ysplive-1.1.12-fnos-all.fpk.sha256` | 校验和 |
| `build-fpk.sh` | 本地一键重建脚本（自动按 manifest 的 appname/version 命名产物） |

## 安装

1. 飞牛 fnOS → **应用中心** → 右下角 **手动安装** → 选择 `ysplive-1.1.12-fnos-all.fpk`；
2. 安装向导里确认**服务端口**（默认 `8767`）与播放参数；
3. 装完桌面出现「ysplive 央视频直播」图标，点开即进入管理界面；应用中心里可启动 / 停止 / 修改配置。

> ⚠️ **改名注意**：应用内部名从 `ysp-live` 改为 `ysplive`，在应用中心里是**一个新应用**。如果之前装过旧包，请先卸载旧的「央视频直播 / ysp-live」（它会占着 8767），再装这个，否则端口冲突会启动失败。旧包的界面配置位于旧应用目录，不会自动带过来，重装后在界面里重设即可。
>
> ⚠️ 如果设备上还跑着旧的 **Docker 版** ysp-live，同样占用 8767，请先 `docker rm -f ysp-live`，或在向导里换端口（安装时会检测端口占用，被占用会明确报错并阻止安装）。

命令行安装 / 卸载：

```bash
sudo appcenter-cli install-fpk /vol1/1000/ysplive-1.1.12-fnos-all.fpk
sudo appcenter-cli status --appname ysplive
sudo appcenter-cli uninstall ysplive
```

## 观看界面

桌面图标打开的就是它，也可以直接访问 `http://NAS地址:8767/`（IPv6 用 `http://[IPv6地址]:8767/`）。

界面是三栏结构，操作只有两步：

| 区域 | 内容 |
| --- | --- |
| 左栏 · 频道列表 | 频道编号 + 名称 + 当前在播节目，选中行为金色高亮；顶部可按「全部 / 央视 / 卫视 / 自定义」分组筛选（宽约 258px） |
| 中栏 · 频道信息 | 频道编号、名称、分组、「正在观看」标记、**正在播出**与**稍后播出**（节目名 + 起止时间）、信号来源与线路说明；宽约 276px，三段信息等距分布、标题下加分隔线 |
| 右栏 · 直播画面 | HLS.js 直接播放，左上标签显示当前线路，右下可全屏 |

**打开即播 · 点一行换台**：应用一打开就自动播放第一个频道（CCTV-1），不需要再点按钮；点频道列表任意一行会立即切到该频道，频道栏保持展开可继续挑台。

**节目单**：界面启动后会自动拉取公开节目表（XMLTV），按 `tvg-id` 把 CCTV-1 / CCTV-5+ / 北京卫视等对上号，所以「正在播出 / 稍后播出」是真数据，不是写死的文案。节目表缓存 30 分钟刷新一次，拿不到时显示「—」，不影响播放。

**全屏收看 · 单击弹选台浮层 · 双击进/退全屏**：

| 操作 | 效果 |
| --- | --- |
| 打开页面 | **自动开始播放**第一个频道，直接进入播放视图：隐藏顶栏与页脚，画面铺满窗口（被浏览器拦截自动播放时会先静音播起来，画面中央出现「点击画面开始播放」，点一下即带声音播放） |
| 播放中单击画面 | 弹出半透明选台浮层：左侧频道列表、中间频道信息（正在观看标记），两块面板合成一张卡片（无缝隙）；右上「主线路 / 管理 / 全屏 / 收起」 |
| 浮层里点一行 | **立刻**换到该频道，浮层与频道栏都保留，可继续挑台（不再自动收起列表） |
| 再单击画面 | 立刻收起浮层继续看；9 秒无操作也会自动收起 |
| 播放中双击画面 | 进入系统全屏 / 再双击退出系统全屏；双击按「350ms 内同一位置」判定，不拖慢单击 |
| 右上「管理」 | 全屏下也能直接打开管理面板（自动退出全屏） |
| 按 Esc 或点「收起」 | 回到三栏界面，播放不中断（画面回到右侧窗口） |

**主备双线路**：

| 线路 | 含义 |
| --- | --- |
| 主线路 | 浏览器直连央视 CDN（部分网络/浏览器会被跨域或缓存策略拦住） |
| 备用线路 | 经 NAS 同源代理 `/api/play.m3u8?…&proxy=1` 转发分片，绕开跨域 |
| 自动切换 | 主线路报错，或**连续 20 秒没有画面**，自动切到备用线路并提示 |
| 手动切换 | 右上角「主线路 / 备用线路」按钮随时切，切完立即重新拉流 |

## 管理面板

右上角「管理」打开展开面板（也可以访问 `/?admin=1` 直接打开），原有的编辑能力都在里面：

| 可改项 | 说明 |
| --- | --- |
| 站点标题 / 公告 | 页面顶部显示的文字，只影响界面观感 |
| 频道名称 | 内置频道改名，订阅单同步生效 |
| 频道分组 | 改成「央视」「卫视」或任意分组名，电视端分组随之变化 |
| 内置频道地址 | 默认由程序自动解析；填了自己的 m3u8 就改用你的源，留空即恢复 |
| 隐藏频道 | 从订阅单中剔除某一路，随时可重新显示 |
| 自定义频道 | 名称 + 分组 + 地址 + 台标，追加到订阅单末尾 |

面板里还有订阅地址一键复制、按关键词搜索频道、运行信息（服务状态、频道数、设备协议池、分片缓存、端口、节目单状态、访问方式）。自定义频道统一走 `/ext` 外链代理，顺带解决 m3u8 里的相对路径与 CORS。

**保存位置**：界面里改的内容存在 `$TRIM_PKGVAR/data/ui-config.json`，节目单缓存是同目录的 `epg.json`，升级保留、卸载清理；上游引擎自己的状态（设备身份、频道缓存）存在同目录的其它 json，二者互不干扰。

## IPv6 支持

- 界面服务用双栈套接字绑定（`::` 且关闭 `IPV6_V6ONLY`），**同一个端口 IPv4 / IPv6 都能进**；系统不支持 IPv6 时自动回退纯 IPv4，不会启动失败。
- 订阅单与分片地址按请求的 `Host` 头生成，IPv6 访问时自动带上方括号形式，例如 `http://[2409:xxxx::1]:8767/cctv1.m3u8`，播放器可直接使用。
- 家宽 IPv6 通常是公网地址（如 `2409:` 开头）且没有 NAT，路由器放行该端口后即可从外网访问；飞牛网关、桌面图标不受影响。
- **修改权限**：内网 IPv4（10/172.16/192.168/127/169.254）、IPv6（回环、链路本地、ULA、公网全球单播）都允许改配置；只有**公网 IPv4** 来源是只读。页面底部会显示当前访问方式。
- 上游引擎仍只监听 `127.0.0.1:8788`，只走 IPv4 回环，不对外暴露。

## 装完怎么用

| 用途 | 地址 |
| --- | --- |
| 管理界面（桌面图标指向这里） | `http://NAS地址:8767/` |
| 全频道订阅（填到电视/播放器） | `http://NAS地址:8767/all.m3u` |
| 只看央视 / 只看卫视 | `http://NAS地址:8767/all.m3u?group=央视` |
| 只看 4K/8K 频道 | `http://NAS地址:8767/all.m3u?k4=1` |
| 单频道直连（给播放器单路用） | `http://NAS地址:8767/cctv1.m3u8` |
| 系统健康度（JSON） | `http://NAS地址:8767/health` |
| 实时诊断报告（纯文本） | `http://NAS地址:8767/diag` |

`/all.m3u`、`/cctvX.m3u8`、`/proxy.ts`、`/health`、`/diag` 全部由界面进程转发给内部引擎，并透传原始 `Host`——上游是按请求 Host 拼分片地址的，所以电视/播放器拿到的地址天然指向界面端口，不需要改写播放列表。

## 架构

```
浏览器 / 电视（IPv4 或 IPv6） ──► 端口 8767  ui-server.py（双栈）
                     ├─ /                管理界面（web/index.html）
                     ├─ /api/state       状态 + 频道列表 + 访问方式
                     ├─ /api/config      GET/PUT 配置
                     ├─ /api/play.m3u8   备用线路（分片改写为同源 /proxy.ts）
                     ├─ /api/play.m3u8   内置频道播放（proxy=1 走同源代理）
                     ├─ /all.m3u         合并订阅（覆盖/隐藏/自定义）
                     ├─ /ext             外链 m3u8 代理（解决 CORS）
                     └─ 其它             ──► 127.0.0.1:8788  ysp-live.py（--bind 127.0.0.1）
```

引擎只监听本机回环，外部无法绕过界面直连 8788；这样「界面改的配置」与「用户看到的订阅」永远一致。节目单由后台线程从公开 XMLTV 源拉取（每 30 分钟一次，失败自动换源），只用于界面展示，不参与取流。

## 安装向导参数

| 参数 | 默认 | 含义 |
| --- | --- | --- |
| 服务端口 | `8767` | 管理界面与订阅共用的 HTTP 端口（IPv4/IPv6），1024–65535 |
| 高码率模式 | 全部高码率 | `all` 全部高码率频道走设备协议池；`only4k` 仅 4K/8K 走；`no4k` 纯 1080p |
| 单设备并发路数 | `6` | 同时占用高码率配额的上限，`0` 关闭主动轮换 |
| 换台防抖秒数 | `10` | 切台先给 1080p，停留超过该秒数才请求高码率，`0` 关闭 |
| 分片内存缓存 | `200` MB | TS 分片内存缓存，内存紧张的设备可调小 |

这些值写在 `$TRIM_PKGETC/config.conf`，装完后也能在 **应用中心 → 应用设置** 里改，保存后自动重启生效。

## 与 Docker 版的差异

| 项 | Docker 版 | 本原生包 |
| --- | --- | --- |
| 运行方式 | `network_mode: host` 容器 | 应用中心直接常驻，专用包用户 `ysplive` 运行 |
| 进程 | 单进程 + 可选 Node | 双进程：引擎 `127.0.0.1:8788` + 界面 `双栈:$PORT` |
| 界面 | 无（只有接口） | 三栏电视式界面：频道列表 + 频道信息 + 直播画面 |
| 节目单 | 无 | 自动同步 XMLTV，显示正在播出 / 稍后播出 |
| 播放线路 | 单一路径 | 主线路直连 + 备用线路代理，20 秒无画面自动切换 |
| Python | 镜像内 3.12 | 优先用飞牛运行时 `python312`，缺失时回退系统 `python3` |
| Node 伴生引擎 | 启动 8787 | **已禁用**（`--no-engine`），见下方说明 |
| 数据持久化 | `./data` 卷 | `$TRIM_PKGVAR/data`（升级保留，卸载清理） |
| 日志 | `docker logs` | 共享目录 `ysplive/logs/info.log`（文件管理器中可见） |
| 端口 | 8767 硬编码 | 向导可选，桌面图标端口自动同步 |

**关于 Node 伴生引擎**：上游 `ysp-engine.js` 目前只是骨架——`getLiveStreamUrl()` 直接 `return null`，缓存永远不命中，未命中时返回 `503`，实际取流全部由 Python 侧设备协议完成。主程序在 `--no-engine` 下功能完全正常（实测 64 路频道、设备身份就绪、订阅单正常）。fnOS 默认也不带 Node，因此直接禁用，省一个进程和 8787 端口。

## 验证清单

```bash
appcenter-cli status --appname ysplive            # 期望返回 running
cat /var/apps/ysplive/etc/config.conf             # 端口与播放参数
tail -20 /vol1/@appshare/ysplive/logs/info.log    # 启动日志（引擎 + 界面各一行「就绪」）
curl -s http://127.0.0.1:8767/health              # ok:true, channels:64
curl -s "http://[::1]:8767/api/state" | head -c 300    # 双栈：IPv6 同样可读
curl -s http://127.0.0.1:8767/all.m3u | head -6   # 订阅单
```

本地打包前已做的实测（Linux，模拟 `TRIM_*` 环境变量跑完整生命周期）：

- `install_init` / `install_callback` / `start` / `status` / `stop` / `uninstall_init` 退出码全部符合约定（`status` 运行中 0、未运行 3）；
- 双进程启动：引擎 `127.0.0.1:8788`、界面双栈 `*:8767`（`ss -lnt` 显示 `*:8767`），IPv4 与 IPv6 均返回 200；`stop` 两个进程都干净退出、端口释放；
- 双栈实测：`http://127.0.0.1:8767/` 与 `http://[::1]:8767/` 都 200；`/api/state` 经 IPv6 访问 `scope=lan`、可写；
- IPv6 地址生成：`Host: [2409:…]:8767` 时订阅单输出 `http://[2409:…]:8767/cctv1.m3u8`，代理播放列表输出 `http://[2409:…]:8767/proxy.ts?=…`；
- `/health` 返回 `ok:true`、`channels:64`、设备身份就绪；`/api/state` 返回 64 个内置频道与分组；
- 界面静态资源 `/`、`/static/app.css`、`/static/app.js`、`/static/hls.js` 均 200；
- 改配置实测：改 cctv1 名称/分组、给 cctv13 换地址、隐藏 cctv6、新增自定义频道 → 合并订阅单立即体现（名称分组替换、cctv6 消失、自定义频道追加）；
- 播放链路实测：内置频道在 Chromium 里通过 HLS.js 成功播放出画面（`/cctv1.m3u8` 分片、`/proxy.ts` 返回 2.2 MB `video/MP2T`）；`/api/play.m3u8?ch=xx&proxy=1` 把分片改写成同源 `/proxy.ts`；`/ext?u=` 能把外部 m3u8 的 URI 与 `URI="..."` 全部改写成同源地址；
- 非法端口（999 / 非数字）与端口占用（18800 被占）均被拦下并给出中文提示；
- 应用设置改端口 18767 → 18768 并切换 `--only-4k`：配置写入正确、旧端口关闭、新端口 200、桌面入口端口同步；
- 重复 `start` 幂等。

## 重建

```bash
./build-fpk.sh
```

脚本会自动下载 `fnpack 1.2.3` 到 `.bin/`、把 `cmd/*` 恢复可执行位、按 manifest 的 `appname`/`version` 命名产物，并输出 fpk 与 sha256。**必须在 Linux 上打包**，Windows 打包会丢可执行位导致应用中心拒绝安装。
